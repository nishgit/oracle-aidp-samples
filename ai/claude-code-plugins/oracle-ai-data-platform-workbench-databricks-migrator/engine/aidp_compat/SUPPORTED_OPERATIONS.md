# aidp_compat — Supported Operations

Version: **0.5.0** (wheel: `aidp_compat-0.5.0-py3-none-any.whl`)
OCI auth: **API key** via `/Workspace/<oci-config-workspace-path>` (DEFAULT profile).
Override with env vars: `OCI_CONFIG_FILE` / `OCI_CONFIG_PROFILE`.

> Resource principal auth is NOT used (known failure modes on AIDP; forbidden by policy).

---

## 1. `dbutils.fs.*` — File System Operations

Import:

```python
from aidp_compat import dbutils
```

All `dbutils.fs.*` methods support **two path types**:
- **OCI Object Storage** — `oci://<bucket>@<namespace>/<key>` (uses OCI Python SDK with API key)
- **Local filesystem** — `/Workspace/...`, `/Volumes/...`, `/tmp/...`, etc. (uses native `os`/`shutil`)

`dbfs:/...`, `/mnt/...`, `s3://...` paths are auto-translated to `oci://` via the mount config first.

| Method | Signature | OCI | Local | Recurse | Notes |
|---|---|:---:|:---:|:---:|---|
| `ls` | `dbutils.fs.ls(path) -> List[FileInfo]` | ✅ | ✅ | n/a | Returns FileInfo (path, name, size, modificationTime, isDir, isFile). Subdirectories appear as `isDir=True`. |
| `cp` | `dbutils.fs.cp(src, dst, recurse=False) -> bool` | ✅ | ✅ | ✅ | All 4 directions: oci↔local, local↔local, oci↔oci. `recurse=True` walks a "directory" (prefix). |
| `mv` | `dbutils.fs.mv(src, dst, recurse=False) -> bool` | ✅ | ✅ | ✅ | Cross-scheme = copy then delete src. |
| `rm` | `dbutils.fs.rm(path, recurse=False) -> bool` | ✅ | ✅ | ✅ | Recurse for prefix removal. |
| `mkdirs` | `dbutils.fs.mkdirs(path) -> bool` | ✅ | ✅ | n/a | OCI: writes a zero-byte placeholder ending in `/` (Object Storage is flat). Local: `os.makedirs`. |
| `head` | `dbutils.fs.head(path, max_bytes=65536) -> str` | ✅ | ✅ | n/a | OCI: uses Range request for partial download. Returns UTF-8 string. |
| `put` | `dbutils.fs.put(path, contents, overwrite=False) -> bool` | ✅ | ✅ | n/a | Raises `FileExistsError` if `overwrite=False` and target exists. |
| `mount` | `dbutils.fs.mount(source, mountPoint, ...) -> bool` | n/a | n/a | n/a | Path mapping only (not a real FUSE mount). Stored in memory + env vars. |
| `unmount` | `dbutils.fs.unmount(mountPoint) -> bool` | n/a | n/a | n/a | Removes a path mapping. |
| `mounts` | `dbutils.fs.mounts() -> List[MountInfo]` | n/a | n/a | n/a | Lists current mappings. |
| `refreshMounts` | `dbutils.fs.refreshMounts() -> bool` | n/a | n/a | n/a | Reloads `AIDP_MOUNT_CONFIG` json. |
| `updateMount` | `dbutils.fs.updateMount(source, mountPoint, ...) -> bool` | n/a | n/a | n/a | Alias for `mount`. |
| `help` | `dbutils.fs.help([method]) -> None` | n/a | n/a | n/a | Prints help text. |

**Implementation note**: All file-content ops use OCI Python SDK directly (no `jvm.org.apache.hadoop.fs`). Works in both interactive notebooks AND scheduled workflows. `copy_object` waits for OCI's async work-request to COMPLETE (up to 300s timeout).

## 2. Other `dbutils.*` Namespaces

| Namespace | Status | Notes |
|---|---|---|
| `dbutils.fs.*` | ✅ Full | See table above. |
| `dbutils.widgets.*` | ✅ | Backed by `oidlUtils.parameters` on AIDP. Use `oidlUtils.parameters.getParameter("name", "default")` for new code. |
| `dbutils.secrets.*` | ✅ | **Vault-only by default**: OCI Vault (API key auth), requires `AIDP_VAULT_OCID` env var + secret named `<scope>/<key>`. Plaintext `AIDP_SECRET_<SCOPE>_<KEY>` env vars and the JSON file named by `AIDP_SECRETS_FILE` are consulted only with `AIDP_ALLOW_PLAINTEXT_SECRETS=1` (file must be `0600` on POSIX; one `insecure plaintext secrets mode active` log line, never values). `AIDP_SECRET_SCOPES=<scope,scope>` and `AIDP_SECRET_KEYS=<scope/key,scope/*,...>` restrict `get`/`list`/`listScopes` (read per call; `none` = nothing allowed; a refusal is logged as `NBP-RUNTIME-SECRET`); `job_migrate.py` derives both from the `dbutils.secrets.get(scope, key)` literals of the planned notebooks and declares them in the cluster bootstrap (an operator-provided value wins). | `dbutils.credentials.*` | ⚠️ | Stub only. Use API key auth directly. `assumeRole` not supported. |
| `dbutils.data.*` | ⚠️ | Stub. Use pandas `describe()` instead. |
| `dbutils.jobs.*` | ✅ | `dbutils.jobs.taskValues.get/set` works. |

## 4. `aidp_compat.safe_io` — Spark-Safe I/O Helpers

For situations where naive `df.write.parquet(...)` / `pickle.dump(...)` can corrupt or lose data on AIDP. Import individually:

```python
from aidp_compat import safe_pickle_dump, safe_pickle_load, safe_write_parquet, ...
```

| Function | Purpose |
|---|---|
| `safe_pickle_dump(obj, path)` / `safe_pickle_load(path)` | Atomic pickle write/read (handles FUSE write-then-read consistency) |
| `safe_write_parquet(df, path, mode="overwrite", partitionBy=None)` | DataFrame write with overwrite-safety (clears stale `_temporary` dirs) |
| `safe_save_as_table(df, table_name, mode="overwrite", ...)` | Like saveAsTable but with retry + cleanup |
| `safe_read_modify_write_parquet(...)` | Read + transform + write back without leaving the original in inconsistent state |
| `safe_write_parquet_coalesced(df, path, num_files=1, ...)` | Write N target files (use for small-result optimization) |
| `safe_save_as_table_coalesced(...)` | Same coalesce + saveAsTable |
| `safe_pandas_to_csv(pdf, path, ...)` | Pandas → CSV with `/Volumes` FUSE retry |
| `safe_materialize(df)` / `safe_unpersist(df)` | Force-cache + cleanup helpers |
| `safe_read_file(path)` | Read text file with FUSE retry |
| `load_saved_model_from_volumes(path)` | Read model artifacts from `/Volumes/...` (handles FUSE delays) |
| `safe_joblib_dump(obj, path)` / `safe_joblib_load(path)` | joblib with FUSE-safe semantics |

All `safe_io` helpers are **pure Python / PySpark** — no JVM Hadoop FS dependency.

## 7. `aidp_compat.oci_throttle` — Object Storage Tuning

For bulk migrations or high-concurrency object-storage workloads:

```python
from aidp_compat.oci_throttle import tune_for_parallel_migration
tune_for_parallel_migration(spark, concurrent_jobs=48, verbose=True)
```

## 8. `aidp_compat.notebook_policy` — Mandatory Sandbox Gate

Runtime enforcement at the execution sink. `dbutils.notebook.run(...)`, `dbutils.fs.rm/mv/cp/put/mkdirs` and every `safe_io` write helper refuse to run until a sandbox is declared; undeclared = `PermissionError` naming the missing variables (fail closed).

| Variable | Meaning |
|---|---|
| `AIDP_SANDBOX_CATALOG` / `AIDP_SANDBOX_SCHEMA` | Only `catalog.schema` that `saveAsTable` / `insertInto` / `writeTo` / `CREATE TABLE` / `INSERT` / `DROP` / `MERGE` / `DELETE` may target (1-part names count as outside) |
| `AIDP_SANDBOX_PREFIX` | Comma list of prefixes that path writes, `dbutils.fs` deletes/moves/mkdirs, `os`/`shutil`/`pathlib` file operations and absolute `open()` must stay under. The first entry is the object-storage prefix (`oci://bucket@ns/path/`); the rest are staging areas. Paths are canonicalised first; a `..` segment is always outside, and on POSIX a symlink inside a prefix pointing outside is outside |
| `AIDP_SANDBOX_ALLOW_NETWORK` | `1` permits `socket` / `requests` / `urllib` / `urllib3` / `httpx` / `aiohttp` / `http.client` / `paramiko` / `ftplib` / `smtplib` / ... imports (default off) |
| `AIDP_NOTEBOOK_POLICY_ALLOW` | Comma list of rule ids accepted as a reviewed exception (logged as `allowed_exception`) |
| `AIDP_NOTEBOOK_POLICY_LOG` | Optional JSONL file mirroring the in-process policy log |
| `AIDP_SECRET_SCOPES` / `AIDP_SECRET_KEYS` | `dbutils.secrets` allowlist (scopes; `scope/key` or `scope/*`), see `dbutils.secrets.*` above; `none` = nothing allowed |

Or declare programmatically: `from aidp_compat import SandboxPolicy, set_sandbox_policy; set_sandbox_policy(SandboxPolicy(catalog="default", schema="<sandbox>", prefix="oci://<bucket>@<ns>/<sandbox>/", extra_prefixes=("/Volumes/default/default/dbfs/",)))`.

**Declared once, frozen for the kernel.** The first policy resolved (explicit object, or the environment on first use) is a one-shot snapshot: later `AIDP_SANDBOX_*` changes are ignored by every assertion, and `set_sandbox_policy` with a different policy (or `None`) is refused as `NBP-POLICY-TAMPER`. Re-running the same declaration (bootstrap replay on reconnect) is a no-op.

**What `job_migrate.py` declares** on every cluster connect and per task (`build_sandbox_policy_snippet`; an operator-provided variable wins and replaces the whole list):

| Prefix | Why |
|---|---|
| `oci://<oci_backup_bucket>@<WORKSPACE_NAMESPACE>/` | the write-redirect bucket; every OCI write the migrator produces lands here |
| `/Volumes/default/default/dbfs/` | the `/dbfs/` and `dbfs:/` translation target the migration prompt rewrites paths to |
| `/tmp/` | local-disk staging the prompt prescribes for torch / h5py / sqlite before copying to `/Volumes` |
| `<output-base>/` | the tool's own output directory (`task_values.json`, `manifest_params.json`, reports) |

Together with catalog `default` / schema `<oci_backup_bucket>_overwrite` and the planned `dbutils.secrets` allowlist (section `dbutils.secrets.*`). Everything else on `/Volumes`, `/Workspace` or in other buckets stays refused.

**Static resolution.** A target that is a plain name bound exactly once (in this or an earlier cell of the run, at module level including `for` / `while` / `if` / `with` / `try` bodies but not inside a function or class body) to a string literal is checked as that literal; `import x as y`, `from m import n as y`, `y = dbutils.fs`, `sp = spark`, `f = getattr`, `b = __builtins__`, `o = os` aliases are followed across cells and the alias is checked exactly like the thing it stands for. A name that once stood for a gated module, protected root, Spark object or dangerous builtin and is later rebound to something the gate cannot resolve (`f = make_getter()`, `os = fake()`) is refused wherever it is used afterwards (`NBP-INDIRECT`, fail closed). Anything else that is not a literal is a `*-DYNAMIC` refusal unless its rule id is in `AIDP_NOTEBOOK_POLICY_ALLOW`.

**Magic-led cells.** A cell whose first line is `%...` or `!...` is skipped as a whole by `dbutils.notebook.run`: no line of it is compiled or executed, and the skip is recorded in the policy log as `skipped_magic` (notebook path, cell index, first line). A `%magic` / `!command` line further down a cell is a `SyntaxError` for `exec`; the gate reports it as `NBP-OS-PROCESS` / `NBP-IPYTHON-ESCAPE` instead so the attempt is logged.

**Runtime SQL guard.** For the duration of `dbutils.notebook.run` (installed before the first cell, removed when `run` returns, so the migrator's own code is unaffected) the session's SQL entry points are wrapped (`aidp_compat.notebook.SqlRuntimeGuard`): `spark.sql` / `sqlContext.sql` on every session object bound under a Spark root name in the executing namespace (the instance and its class), the importable `pyspark.sql.SparkSession` / `SQLContext` classes (so a session fetched with `getOrCreate()` inside `sql_magic.sql()` is covered too), `spark.table` on the same session objects and `pyspark.sql.DataFrameReader.table`, `pyspark.sql.DataFrame.selectExpr` / `filter` / `where` (string form), `pyspark.sql.functions.expr` and the Java-call functions `pyspark.sql.functions.reflect` / `java_method` / `try_reflect` / `call_function` (each also under every name the namespace bound it to). Each wrapper runs `classify_sql` (statements, after the same `{name}` keyword rendering pyspark performs), the expression classifier (refuses `reflect(` / `java_method(` / `try_reflect(`, quoted or not, and the script transform), the table-read rule (a path table on the local filesystem outside the prefix) or the function-name rule on the FINAL value with the run's `SandboxPolicy`, appends a `runtime_refused` entry (operation, rule, target, notebook path, cell index) to the policy log and raises `PolicyViolation` before Spark executes anything. Without `pyspark` the class patches are no-ops; the session-object patches work on any object with a callable `sql` / `table`. Because the guard lives on the session object, `spark.newSession()`, `SparkSession.builder..getOrCreate()` and `SparkSession.getActiveSession()` are refused statically (`NBP-POLICY-TAMPER`): a fresh or fetched session object would not carry it.

**Scope of the gate.** It is a static check of the forms listed above, not a Python sandbox, and a static AST gate over a full Python runtime is a mitigation layer: the platform-level control is the IAM scope of the cluster the notebook runs on (what the cluster's principal may read, write and call), and the runtime assertions are the enforcement layer for every write that goes through the compat helpers (`dbutils.fs.*`, `safe_io`, `dbutils.secrets`); Spark writes are covered by the AST rules plus the migrator's write-redirect interceptors. Not covered, by design or by limit: direct OCI SDK calls (`import oci` is allowed because migrated notebooks use the API-key init pattern); reads of source data through variables (`spark.read.parquet(src)`, `pd.read_csv(path)`): a reader path the gate cannot resolve is allowed and only recorded (`unverified_read_path`), because reading source data through parameters is the normal migration case and the cluster's IAM scope is the control there, and object-storage (`oci://`, `abfss://`, `s3://`) and catalog-table reads are never path-checked (a literal local path is, see `NBP-OPEN-PATH`); `spark.sql` statements with run-time fragments whose literal head verb is a read verb, only while the runtime SQL guard of `dbutils.notebook.run` is active (recorded as `unverified_sql_read`; the guard judges the final text, see `NBP-SQL-REFUSED`; a bare static scan refuses them as `NBP-SQL-DYNAMIC`); `spark.table(name)` with a dynamic name (recorded as `unverified_read_path`; the runtime guard refuses a path table on the local filesystem when the name is known); `spark.read.format(fmt)` / `df.write.format(fmt)` with a provider the gate cannot resolve while the sandbox allows no network access (recorded as `unverified_format`; a literal network provider is refused, the cluster's network egress is the control for the rest); the string-literal lexing of Spark's default parser (`\` escapes in ordinary literals, none in `r'..'`): the session conf `spark.sql.parser.escapedStringLiterals`, which would change it for every literal, is refused in the notebook (`SET` and `spark.conf.set`), but a cluster that sets it globally is outside the gate's view; `DataFrame.pipe(name)` where `name` is a bare name the gate cannot type on a bound, non-Spark receiver (a function the notebook did not `def`; recorded as `unverified_pipe_callable`, while a string-typed argument, a Spark / RDD receiver or a receiver the notebook never bound is refused); `<object>.open(path)` on a receiver the notebook bound that is neither the builtin, a stdlib module nor a `Path`, with a dynamic path (an object-store filesystem; recorded as `unverified_read_path`; a receiver the notebook never bound is refused); native Spark writers reached through objects the gate cannot name (a `DataFrameWriter` returned by a function or taken from a collection; a writer / reader bound to a plain name, also through a builder chain or an alias of the name, is followed, see `NBP-PATH-WRITE`); the code of imported modules, including the in-tree module mirror the migrator itself puts on `sys.path` (`sys.path.insert` is therefore allowed; a notebook that writes a `.py` file into the sandbox and imports it runs unscanned code); third-party string evaluators (`sympy.sympify`, `jinja2` templates, `pandas.eval` / `DataFrame.query`); `spark.conf.get` and `sparkContext.getConf()` reads; directory listing (`os.listdir`, `Path.glob`); `tempfile` with the default directory or a `dir=` the gate cannot resolve (a literal `dir=` / absolute `prefix=` outside the prefix is `NBP-FS-PATH`); a dynamic path on a generic `.save(..)` / `.export(..)` receiver (`model.save(uri)`: the receiver cannot be typed; the unambiguous library writers fail closed, see `NBP-PATH-WRITE`); `input()` / `help()`. `CREATE [OR REPLACE] [GLOBAL] TEMP VIEW` without `LOCATION` and plain `SELECT` are reads; a statement starting with `WITH` is whatever follows its CTE list. `dbutils.fs.mount(...)` keeps `extra_configs` in memory only (never in the process environment).

**Known false refusals** (deny-by-default; rewrite the cell or list the rule id in `AIDP_NOTEBOOK_POLICY_ALLOW` after review): `self.__dict__.update(kwargs)` and other `__dict__` reads (`NBP-DUNDER-ESCAPE`, use explicit attributes); `for k, v in opts.items(): setattr(self, k, v)` (`NBP-INDIRECT`, non-literal attribute name); iterating `globals()` / `locals()` (`NBP-INDIRECT`); `gzip.open(path_var)` and the other open-equivalents with a non-literal path (`NBP-OPEN-DYNAMIC`, same rule as `open(path_var)`); `torch.load(p)` (`NBP-DESERIALIZE`, pass `weights_only=True`), `pd.read_pickle` / `pickle.load` of your own files (`NBP-DESERIALIZE`, use parquet / json or allowlist); `spark.sparkContext._conf.getAll()` (`NBP-POLICY-TAMPER`, use `spark.sparkContext.getConf().getAll()`); `os._exit`; a name once bound to `spark` / `os` / `getattr` and later reused for something else (`NBP-INDIRECT`, use a fresh name); `%timeit` / `%%time` lines inside a cell body (`NBP-IPYTHON-ESCAPE`, they would not `exec` anyway); `tpl.format(obj)` / `TEMPLATES["x"].format(row=row)` where the template is not a literal the gate can resolve (`NBP-DUNDER-ESCAPE`, inline the template or bind it once to a literal); `writer.format(fmt_var)` on a `DataFrameWriter` the gate cannot follow (returned by a function, taken from a collection; `NBP-DUNDER-ESCAPE`, bind the writer to a plain name from `df.write...`, which is followed, or bind `fmt_var` once to a literal); `spark.sql(f"USE {db}")`, `spark.sql("  " + q)`, `spark.sql(f"WITH x AS ({sub}) SELECT ..")` (the CTE list is not literal) and other dynamic statements without a literal read-verb head, and every dynamic statement in a bare static scan outside `dbutils.notebook.run` (`NBP-SQL-DYNAMIC`, bind the whole statement to a literal); `spark.sql("SELECT * FROM IDENTIFIER('t')")` and every `IDENTIFIER(..)` clause (`NBP-SQL-DYNAMIC`, spell the name literally); `spark.sql("DROP TABLE {t}", t=name)` and other `{name}` templates whose head is not a read verb or whose values are not literals (`NBP-SQL-DYNAMIC`, pass literal values or bind the whole statement to a literal); `spark.read.format("jdbc")` / `spark.read.jdbc(..)` / `CREATE TEMP VIEW .. USING jdbc` and the other network providers with `AIDP_SANDBOX_ALLOW_NETWORK` off (`NBP-IMPORT-NETWORK`, declare the network posture after review); `spark.conf.set("spark.databricks.delta.schema.autoMerge.enabled", ..)` and other confs outside the `SET` allowlist (`NBP-SQL-REFUSED`, configure the cluster); `spark.catalog.setCurrentDatabase(db)` with a dynamic name (`NBP-SQL-DYNAMIC`); `spark.sql("DROP VIEW tmp_v")` on a temp view (`NBP-SQL-TARGET`, a 1-part name; temp views end with the session); `spark.sql("FROM t SELECT *")`, `SET spark.sql.<conf outside the allowlist>`, `SELECT TRANSFORM(..) USING 'cmd'`, `ADD JAR`, `CREATE FUNCTION` and the other forms outside the SQL allowlist (`NBP-SQL-REFUSED`, express the step in PySpark or configure the cluster); `df.selectExpr("reflect(..)")` / `F.expr("java_method(..)")` at run time (`NBP-SQL-REFUSED`, use a built-in function or a Python UDF); `pd.read_csv("/Volumes/prod/in.csv")` and other literal local reads outside the prefix (`NBP-OPEN-PATH`, read through `oci://` or declare the volume as a prefix); `open(path_var)` / `open(f"{d}/x.json")` and the other open-equivalents with a non-literal path, in read mode as well (`NBP-OPEN-DYNAMIC`, bind the path once to a literal, or read through `pd.read_*` / `spark.read`, which are recorded instead); `def get_spark(): return spark`, `sessions = [spark]`, `run(os)` and other code that hands a module or Spark object around as a value (`NBP-INDIRECT`, use the object by its own name where it is needed); `platform.system()` or `self.fork()` with no `import platform` / resolvable receiver in view (`NBP-INDIRECT`, import the module in the notebook, or rename a method that collides with a process sink name); `operator.attrgetter(field_name)` with a run-time name (`NBP-INDIRECT`, use a literal); subclasses of `yaml.SafeLoader` even without constructors (`NBP-DESERIALIZE`, use `yaml.safe_load`); `np.load(p, allow_pickle=flag)` (`NBP-DESERIALIZE`, pass the literal `False`); `globals()["my_var"].attr` (`NBP-INDIRECT`, read `my_var` directly); `thing.open(p)` / `thing.pipe(fn)` where `thing` was never bound in the notebook (`NBP-OPEN-DYNAMIC` / `NBP-OS-PROCESS`, bind the object in the notebook first); `import mymod; mymod.system(..)` and other process sink names on your own modules (`NBP-INDIRECT`, rename the function); `mymod._helper` (`NBP-INDIRECT`, use a public name); `np.load(p, None, True)` / `np.load(p, **kw)` / `loader.load(p, **kw)` (`NBP-DESERIALIZE`, pass `allow_pickle=False` as a literal keyword); `yaml.SafeLoader.yaml_constructors[..] = ..` and other writes into a gated module's state (`NBP-DESERIALIZE` / `NBP-POLICY-TAMPER`); `parts = [..]; parts.append(x); open("/".join(parts))` (`NBP-OPEN-DYNAMIC`, build the path as one literal); `import site` / `pip.main(..)` (`NBP-BUILTIN-EXEC`, install as a cluster library); `df.to_csv(out_path)` / `np.save(out, a)` / `plt.savefig(fname)` / `fig.savefig(buf)` where the path is not a literal the gate can resolve and `buf` is not a `StringIO` / `BytesIO` / `ExcelWriter` the notebook bound once (`NBP-PATH-WRITE-DYNAMIC`, the same rule as `df.write.parquet(path_var)`: bind the path once to a literal sandbox path, write through `df.write` / `dbutils.fs`, or allowlist after review); `df.to_csv(fh.name)` on a `NamedTemporaryFile` (`NBP-PATH-WRITE-DYNAMIC`, write under a literal sandbox directory instead); `tempfile.mkdtemp(dir='/tmp')` when `/tmp/` is not a declared prefix (`NBP-FS-PATH`; the migrator's bootstrap declares it); `traceback.walk_stack(None)` / `capture_locals=True` (`NBP-INDIRECT`, use `extract_stack()` / `format_exc()`). Every refusal, allowed exception, skipped magic cell, unverified read (`unverified_read_path` / `unverified_sql_read`), runtime refusal (`runtime_refused`, from the compat helpers and the runtime SQL guard) and sandbox declaration is appended to the policy log (`get_policy_log()`, `policy_log_markdown()`); `job_migrate.py` pulls it into each task's test report as **Notebook Policy Log**.

## 9. What NOT to Use in Migrated Notebooks

❌ **Direct JVM Hadoop FS calls** — `spark._jvm.org.apache.hadoop.fs.FileSystem.get(...)`, `fs.open(...)`, `fs.exists(...)`. These FAIL in scheduled workflow runs even though they work interactively.
**Use instead**: `dbutils.fs.*` (above) or OCI Python SDK directly.

❌ **`oci.auth.signers.get_resource_principals_signer()`** — Known failure modes on AIDP.
**Use instead**: API key auth (see top of this doc).

❌ **`boto3` for S3** — AWS SDK not configured on AIDP.
**Use instead**: `aidp_compat.s3_compat` for routing, or OCI SDK directly.

❌ **`dbutils.notebook.run(path, 0, ...)`** — AIDP rejects `timeout=0`.
**Use instead**: `oidlUtils.notebook.run(path, timeout=3600, ...)`.

## 10. Quick Smoke Test

After installing the wheel, run this in a notebook to verify install:

```python
import os
from aidp_compat import dbutils

OCI_BASE = "oci://<oci_backup_bucket>@<WORKSPACE_NAMESPACE>/aidp_compat_smoke"
# Declare the sandbox first: dbutils.fs writes refuse without it (section 8).
os.environ.setdefault("AIDP_SANDBOX_CATALOG", "default")
os.environ.setdefault("AIDP_SANDBOX_SCHEMA", "<sandbox_schema>")
os.environ.setdefault("AIDP_SANDBOX_PREFIX", OCI_BASE + "/")
dbutils.fs.put(f"{OCI_BASE}/hi.txt", "hello", overwrite=True)
print(dbutils.fs.head(f"{OCI_BASE}/hi.txt", 100))
dbutils.fs.rm(f"{OCI_BASE}/", recurse=True)
print("✓ smoke test passed")
```
